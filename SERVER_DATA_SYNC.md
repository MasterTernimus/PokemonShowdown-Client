# Approved local server data

The client keeps generated data assets out of Git. `node build` alone does not refresh those assets. Do not publish a code-only checkout with an old `data/` directory.

## Prepare the reviewed release

Check out server commit `eb4df7b2171223918cc79aecd6674292a887aa7c`. Set `PS_SERVER_SOURCE` to that exact approved checkout, then run:

```
node build-tools/prepare-approved-client-data
```

This verifies the exact server commit and reviewed source-data fingerprint (normalized LF line endings), builds that server, generates indexes/data and learnsets directly from it, regenerates minidex dimensions from the tracked sprite artwork, then builds the client. It does not pull, reset, commit, push, deploy, or alter artwork. It never uses or changes `caches/PokemonShowdown-Reborn` when the explicit source is supplied.

The tracked delivery inputs are the generator scripts, `server-data-sync-manifest.json`, and the marked SERVER WORKING SYNC blocks in `src/battle-dex.ts`. The latter are compiled into both `js/battle-dex.js` and tracked `js/battledata.js`, so stale handwritten overrides cannot restore old reviewed values.

A deployment must deliver the freshly generated `play.pokemonshowdown.com/data/*.js` assets together with the compiled client JS, CSS, and built HTML from that same preparation. `client-data-provenance.json` records the generated data hashes for verification; it is a local build receipt, not a source file to stage. Running the preparation script is necessary on a fresh checkout. A Git push by itself does not deliver ignored assets.

## Deliberately review a later server update

Build the chosen server first. Set `PS_SERVER_BASE` to its previously approved revision and run `node build-tools/sync-working-server-data` with `PS_SERVER_SOURCE` set. Review the new manifest and marked override blocks before accepting them. This command identifies changed data entries from the supplied server diff; it refuses an empty diff rather than erasing an approved snapshot. Do not blindly rerun it against HEAD after committing the server changes.

## Verification

`node node_modules/mocha/bin/mocha test/server-data-sync.test.js` checks the individual scripts and combined bundle against the reviewed snapshot.

For browser parity and UI regressions, install/use Playwright and run `node test/battle-tools-browser.cjs` with `PS_SERVER_SOURCE` set. `PLAYWRIGHT_MODULE` may point to an existing Playwright installation; `BROWSER_CHANNEL=msedge` selects local Edge. This checks the actual browser Dex against the server, responsive counters, news navigation, and atomic calculator imports. It uses an isolated loopback fixture and does not restart the public service.

The checked-in workflows do not establish a deployment path for main. Confirm the hosting build/asset transfer configuration separately before publication.

Sprite metadata (`data/pokedex-mini.js` and `data/pokedex-mini-bw.js`) is generated by the existing `build-minidex` step from the checkout’s tracked sprites. Preparation includes this step and fails if outputs are absent. Empty animation entries are omitted so the client can use its existing base-species fallback. No sprite download is needed.
